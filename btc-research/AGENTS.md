# BTC 研究项目的 Codex 工作约定

作用域：本目录 `btc-research/`。不覆盖用户全局设置，也不修改上级原项目文件。

## 每次任务开始

- 先读 README.md、docs/PROJECT_SPEC.md、docs/STATUS.md，再读当前阶段实施计划。
- 先运行 `git status --short`、`git branch --show-current`、`git remote -v`；远端地址含凭据时不得原样写入报告。
- 使用独立本地克隆/工作区；存在未提交变更先记录，不 reset、不 clean、不覆盖用户内容。
- 规划来源为 `docs/btc-quant-plan-20260905`。实现使用独立 `work/btc-m1` 分支。获取规划分支不等于它已合并到 main。
- 确认本目录是实际工作目录；不要假设在仓库根目录启动后会自动加载所有子目录指令。

## 范围与保密

- 当前实施范围仅为 M1。M2 以后先提交独立设计与验收条件，不能顺手添加自动下单。
- 不访问私人账户、不读取或索取 API 密钥、私钥、助记词；不实现充值、转账、提现、真实订单或杠杆。
- 不绕过访问限制。网络失败要记录真实失败，仍可完成离线测试；禁止伪造已下载数据或把合成数据当真实行情。
- 不扫描用户全盘，不递归读取原 A 股缓存，不批量上传任何原项目代码/报告。原项目只在用户明确指定路径与范围后做只读审查。
- 原始行情、完整回测产物、日志、数据库、个人配置保存在仓库外部。M1 先实现 .gitignore 与输出路径检查。
- 此承载仓库公开。只推送用户授权公开的新代码、测试、小型合成样本和脱敏摘要。任何可能属于私有策略、账户、个人路径的内容都不得默认公开。
- .gitignore 不会自动停止跟踪已经被 Git 跟踪的文件；提交前必须检查暂存区。禁止 `git add .`、force push、删除分支、自动合并 PR。

## 研究规则

- 内部统一 UTC；显示时区可配置但不得改变分组、信号或标签。
- BTC/USDT 现货数据不等于 BTC/USD 结算参考数据；不得混用交易产品或价格源。
- 2025 年前后 Binance 现货归档时间戳单位需要显式声明、校验与记录，不能靠固定除数处理全部历史。
- 不沿用 A 股 T+1、100 股整手、涨跌停、复权或交易日历逻辑。
- 信号只用已经闭合的数据；先决定、后模拟成交；严格区分研究用分钟开盘成交模型和真实盘口执行。
- 不能用未来实际结果、全样本拟合参数、测试集选参、完整未来窗口统计量生成当时特征。
- 所有费用、滑点、成交假设、参数选择与失败实验都要记录。参数只是研究假设，不是官方费率或已证实最优值。
- 不无限搜索参数，不用高胜率、IC 或年化收益单独证明策略可用。

## 实施纪律

- 按当前实施计划逐项先写失败测试，再实现、跑测试、检查实际输出。
- 离线单元测试不访问网络；联网验收必须显式开启并单列结果。网络测试跳过不等于通过。
- Python 使用项目独立虚拟环境，不修改用户其他项目环境或全局 AGENTS.md。
- 不安装无关服务，不建立复杂前端，不在每分钟交易循环中调用付费语言模型。
- 不宣称工具执行了实际未运行的命令。失败时给命令、脱敏错误与影响；只有测试真正通过才写通过。

## 交付与同步

每个可验收任务结束更新 docs/STATUS.md。运行摘要保存在 docs/reviews/<run_id>.md，必须包含代码提交 SHA、配置/数据哈希、命令、真实测试结果、数据覆盖、已知限制、下一步。

摘要内的 code_commit 指运行所用代码的已有提交；摘要自己的后续提交不能反过来冒充运行代码版本。dirty 工作树需明确记录 diff 哈希，正式结果要求 clean。

只在用户授权后推送指定分支。报告分开写：已编辑、已测试、已提交、本地未推送、已推送。无人值守进程只有在本地实际启动并验证后才能说在运行；对话结束不会自动继续执行。
