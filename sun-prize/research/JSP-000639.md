# JSP-000639 · Primorial plus a prime

## Status

**Background probe only — not a main green-light target.**

This candidate survived the first deep competition search better than most, but preliminary computation does not currently suggest an easy counterexample.

## Official problem

Let

`Pₙ = p₁ p₂ ⋯ pₙ`

be the product of the first `n` primes. Is there always a prime `p` satisfying

`pₙ < p < Pₙ`

such that

`Pₙ + p`

is also prime?

The JSP catalog records this as Open with no Lean proof.

## Why it is computationally attractive

A negative answer has a finite certificate: one explicit `n` for which every prime `p` in the allowed interval makes `Pₙ + p` composite.

That means we can separate the research into cheap stages:

1. scan candidate primes above `pₙ`;
2. use modular sieving to eliminate most `p` without full primality tests;
3. test surviving `Pₙ + p` values;
4. if a counterexample is found, save compositeness witnesses/factors for every admissible candidate needed in the certificate;
5. formalize only the finite certificate in Lean.

A positive computational result for many `n` does not prove the conjecture, so search must have a strict budget.

## Preliminary disposable probe

A short runtime experiment tested `n = 2..100` and found at least one admissible prime `p` for every tested `n` such that `Pₙ + p` was prime. In many cases a witness appeared after only a small number of candidate primes.

This computation was exploratory and is not yet a repository artifact. It must be reproduced by a committed script before being used as evidence.

Interpretation: the conjectured witness appears abundant at small `n`, so a small counterexample does not currently look promising.

## Cheap next experiment

Only if spare compute/time is available:

- build a segmented candidate-prime iterator;
- sieve `Pₙ + p` simultaneously modulo many small primes using `Pₙ mod q`;
- record the first witness and number of tested survivors for each `n`;
- establish empirical search-cost growth;
- stop if witnesses remain abundant and search cost rises without a structural pattern.

## Stop conditions

Retire this target immediately if any of the following occurs:

- a competing public proof/counterexample project appears;
- the witness density stays high across a materially larger range;
- large-integer primality cost dominates without stronger modular elimination;
- no mathematical mechanism emerges suggesting where a counterexample could occur.

## What would upgrade it to a main target

At least one of:

- a long and statistically unusual run where witnesses become rare;
- a modular obstruction that could force all candidates composite for some `n`;
- a construction reducing the search to a finite residue-covering problem;
- a new theoretical observation that narrows candidate `n` dramatically.

Until then, this is a **low-cost lottery ticket**, not where the main research budget goes.
