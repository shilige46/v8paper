## 0. 先读这里：这次到底要做什么

**第一优先级不是做运营后台，也不是先凭空编二十条故事，而是把一条真实 TikTok 参考视频，经过人工筛选、Hypit 拆解编排、Dola 生成和再次人工验收，做成一条本地可播放的新视频。**

完整业务链路如下：

```text
P0：首先完成，允许人工衔接，不要求全自动
TikTok 找爆款候选
  → 核验原链接和可见数据
  → 下载允许保存的参考片，登记来源
  → 人工审参考片，选定一条
  → Codex / ChatGPT 配合 Hypit 理解原片、改写中文剧本和分镜
  → 人工确认分镜与生成范围
  → 导出 Dola 生成任务包
  → 人工在 Dola 提交、等待、下载真实视频
  → 人工审生成片段，不合格则局部修改重做
  → 导入 Hypit，组织字幕、音轨、图形与时间线，渲染新视频
  → 人工验收最终 MP4

P1：P0 完成且使用许可等条件满足后
成片复核 → 人工上传国内抖音 → 记录作品链接、时间和版本

P2：已有真实发布作品后
获取本人后台数据 → 24 小时 / 72 小时 / 7 日快照
  → 比较观看、分享、关注、成本与真实收益
  → 决定下一条选什么、改哪里
```

## 1. 项目目标、范围与协作边界

目标是低投入验证短视频内容与生产流程，不保证回本。主研究范围暂定萌宠/动物拟人搞笑、简单挑战与视觉反转；正式选择哪个结构，先看真实候选和人工判断。

首条内容以 20—35 秒为目标，30 秒作为分镜与成本参照；最多两个主要角色，少量场景和简单动作。不为凑够时长拉长剧情，不强求一镜到底。

本轮只修改策划文件，不执行购买、安装、生成或发布。当前新增支出批准额为 **0 元**；首轮累计上限 **100 元**仅为待用户批准的建议，不是支付授权，也不保证能做满二十条。

仓库当前为公开；工作范围仅 `video-lab/`。不修改根目录原有文件、游戏项目、量化项目、生产服务器、全局配置或全局 AGENTS.md。不上传账号密码、Cookie、验证码、API Key、个人后台隐私截图、无权公开的参考片及大型素材。

由用户负责账号、预算、人工创作判断和最终发布；ChatGPT 负责资料、选片分析、剧本及复盘；Codex 负责已授权本机工作区内的 Hypit 接入、文件管理、渲染、验证和交接。双方通过真实提交和文件协作，不假设自动看见对方本地进度。

执行时在已批准范围内持续推进。仅在人审、账号本人操作、缺少关键素材/权限、新增支出或发布等确实需要用户决定的节点暂停，不把每一次读取文件都变成重新审批。

## 3. 如何查找 TikTok 爆款候选

### 3.1 查找入口与顺序

**入口 A：TikTok 站内搜索和作者主页。** 在用户可正常访问的入口搜索 `funny cat`、`cat comedy`、`cat office`、`animal plot twist`、`pet challenge`、`AI cat story` 等词；进入真实作品页查看完整视频和可见数据，再查看该作者的相关作品。搜索结果或推荐流只能提供线索，不直接证明爆款。

**入口 B：TikTok Creative Center / Trends。** 用于找热门话题、创作者和内容线索，再返回原作品核验。当前入口会跳转，部分内容需要登录；不能承诺任意地区都能看到全量榜单。[S4] `Top Ads` 是广告素材入口，不能把广告曝光当成自然流量爆款。

**入口 C：公开网页检索。** 用 `site:tiktok.com` 加题材关键词找候选，再核验原页。第三方榜单、帖子和分享截图只记为线索；不先买榜单会员、爬虫服务或批量采集软件。

### 3.2 首轮操作数量

先尝试建立 **10 个真实候选 → 筛出 3 个可审参考 → 人工选 1 个生成**。数量是工作上限和目标，不要求凑数；找到足够合适的候选可先完成第一条。暂时找不到可访问或可保存的素材，报告实际缺口，不虚构链接与播放量。

默认观察近 7—30 天的内容，另保留少量更早的高表现结构。记录作品发布时间与数据观察时间，不能把历史累计播放包装成近期增速。

“爆款候选”的试验筛选线可先用：可见播放约百万级；或者明显高于该作者相近题材的常见表现。比较作者基线时保留样本，排除置顶或广告等已知不可比情况；没有足够样本就不计算倍数。这是选片方法，不是预测抖音流量的公式。

### 3.3 候选表必须填什么

```text
candidate_id,source_url,creator,search_query,source_entry,
published_at,observed_at,duration_seconds,
views_display,views_numeric,views_is_approx,likes,comments,shares,
viral_evidence,author_baseline_notes,opening,conflict,payoff,
production_difficulty,download_status,rights_notes,selection_status
```

播放显示为 `1.2M` 时保留原显示值，若换算同时标明近似；没有分享数就留空。每个候选写一句“为什么值得做”和一句“什么地方可能做不出来”。

### 3.4 内容筛选约束

优先选择：无需大量口播即可理解；20—35 秒可讲完；一到两个主角；动作能拆为几个短镜头；有清楚的开头、变化和笑点；可用新的中文情境与角色重写。

降低优先级：多人打斗、密集物体交互、复杂口型、依赖名人/知名 IP、主要吸引力来自受限音乐、以伤害动物或虚假真实事件博眼球。

候选确定前，不提前花钱做整套角色资产，也不让自拟原创选题替代真实 TikTok 输入。

## 4. 如何下载参考视频与保管素材

### 4.1 首轮具体下载路线

1. 打开已核验作品，保存原作品链接及作者信息；在 App 的分享菜单检查是否有“保存视频 / Save video”等官方入口，具体名称以实际界面为准。
2. 当作品允许保存时，使用该入口下载；手机端保存后，由用户通过正常文件传输导入项目本机目录。保留作者/平台标识，不要求无水印原片。
3. 如有作者提供的原文件、自有视频或明确允许使用的下载地址，优先使用其提供方式，并记录授权范围。
4. 保存入口不可用、文件损坏、链接需登录或权限不足时，写明原因。可联系作者取得文件，或从候选池换一条；不把无下载权限当成已经下载完成。

TikTok 帮助中心提供下载相关入口，但本轮正文访问发生跳转且未完整取得；上面是需要在用户实际界面执行并核对的操作流程，不声称已经下载到素材。[S5]

首轮不以付费第三方去水印网站或自建全站爬虫作为前置条件。若后续需要对允许下载的链接做本地自动化，先核验具体工具、站点支持与允许范围，只处理选定作品，并保留官方保存/人工导入作为回退。

### 4.2 文件落盘与检查

建议本机位置：`video-lab/local/references/R001/source.mp4`。该目录先加入项目局部忽略规则，不上传到公开 GitHub。

同时记录来源、下载方式与时间、实际文件大小、SHA-256、时长、画幅、帧率及音轨信息；使用实际媒体探测或播放器检查，不只看扩展名。下载的是网页 HTML、预览图或不完整文件时应被拒绝。

检查原片与作品页是否对应，是否缺开头/结尾、静音或截断。不要为下载同一文件重复消耗额度；同一素材可按哈希识别复用，但不能覆盖原始文件。

### 4.3 区分三种使用范围

`download_permission`、`model_input_permission`、`publish_permission` 分别记录。**允许保存离线观看不自动等于允许上传生成服务、改编或商业转载。** 具体使用依据不明时标记该步骤阻塞，不把“公开视频”当万能授权。

参考片可在允许范围内本地观看分析；输入模型的参考素材使用自有或具备相应权利的内容。原片不具备模型输入许可时，改用人工整理的抽象节奏/叙事笔记与自有视觉素材，不把原片文件上传 Dola。

只借鉴抽象结构，不直接把原片改字幕后发抖音，也不把原片音轨作为成片默认配乐。具体版权判断有疑问时另行确认，不将“AI 重新画了一遍”视为自动免责。

## 5. 人工审核一：这条参考片值不值得做

给用户展示三张简明选片卡，每张有：原链接、本地可播放文件或实际访问说明、可见数据、剧情摘要、建议改法、生成难点和权利情况。可以使用 Markdown 与本机播放器，第一轮不开发复杂审核后台。

用户完整看过后，从以下维度判断：

| 检查点 | 合格表现 |
| --- | --- |
| 开头 | 几秒内知道发生什么，不依赖长解释 |
| 剧情 | 能用一句话说清问题和结尾 |
| 本土化 | 可改为中文观众理解的场景，而非照搬外国文化梗 |
| 可制作性 | 动作数量和难度符合已知生成能力 |
| 新意 | 有重新设计的角色、场景、台词或事件，不只是逐镜复制 |
| 输入可用性 | 文件可读，所需使用范围明确或能用自有素材替代 |

决策只取 `approved / revise / rejected`，记录原因、审核人、时间、参考文件哈希。AI 可以建议，但不能替用户填“人工通过”。换参考片或改变创作方向后，重新审核对应版本。

通过后才给它分配首条制作编号 `V001`。v1.0 的《豪华猫窝与纸箱》只是备用原创练习，不是默认已选参考片，更不能冒充 TikTok 已验证爆款。

## 6. Hypit 是核心：如何接入并完成拆解编排

### 6.1 接入要求

使用 `hypit-ai/hypit` 官方项目的 Skill、工具和示例。先检查已有安装、官方文档、许可与所用版本；缺什么就列什么，不默认运行未知安装脚本或修改全局配置。记录 Hypit 软件版本、Skill 来源及核验日期。

不要求把上游仓库整份复制到我们的仓库，不修改上游默认分支。工作成果保存在 `video-lab/` 内，以后可继续交给 Codex。

Hypit quickstart 的 `/hypit` 是对支持 Skill 的 Agent 的调用方式，不是可以直接在系统终端执行的 shell 命令；是否已被当前 Agent 加载必须实际确认。[S1]

### 6.2 谁负责理解视频

由能实际查看视频内容的 Agent/人工配合 Hypit Skill 分析；Hypit 不是独立保证理解全部视频的模型。必须实际看过完整片段或有足够帧与音轨证据，不只根据标题、缩略图和播放数编分镜。工具不能读取视频时如实报告，使用用户已看过的时间码笔记等补足，不冒充已经观看。

拆解输出至少包含：原片时长、语义段落、镜头起止、开场信息、情绪/笑点升级、结尾、对白/音效功能、字幕/排行/图形出现时机，以及允许借鉴的抽象结构。

然后形成中文新剧本：保留需要验证的叙事机制，重新设计具体场景、人物、台词与动作。新片分镜应说明哪里借鉴、哪里重写、哪些原片元素不能带入。

### 6.3 给 Hypit Agent 的首轮工作指令

```text
/hypit
请读取已人工通过的参考记录和允许分析的本地参考素材。
先真实分析，再为中文观众改写为约 30 秒的新视频。
输出语义段落、中文剧本、分镜、参考图需求、字幕音轨方案和 Dola 任务清单。
本轮生成入口指定 Dola，采用用户人工提交并下载的方式。
不要调用 HypiHub 或任何付费生成、图像、语音、WhisperX 服务。
不要宣称存在未经核验的 Dola API；不要复用无相应许可的原片画面或音乐。
在分镜通过后导出生成包；待本机素材回填后，用 Hypit 编排渲染。
保留可编辑项目和真实构建记录，不只交一个不可追踪的 MP4。
```

### 6.4 Hypit 必须留下的实物

`analysis.md`、`storyboard.csv`、可执行版本支持的作者源文件、运行配置和样式文件，以及真实构建记录。

当前官方文档使用 `main.svml`、`build.svrun`、`recipes.svs` 等形式，并说明 Film/Track 到 MP4 的流程。[S2] 这些文件必须按执行时所用版本的实际语法创建，不能编造 `<dola:Video>` 标签或不存在的命令。

执行者须核对该版本如何注册/引用本地媒体、设置渲染目标和隔离付费 Provider。官方有本地媒体与本地渲染相关包可作为检查线索，但与 Dola 下载素材的实际衔接尚未测试。[S6]

所有素材回填前，项目可以是明确的“等待外部素材”状态；不能为了让 build 变绿，偷偷调用付费模型或用测试视频冒充 Dola 输出。

## 7. 人工审核二：分镜通过后，导出 Dola 生成包

用户先检查新剧本有没有笑点、是否接受角色与改法、哪些镜头需要生成、预计消耗范围。没有必要每个标点都重新批准；明确通过的版本和范围后继续推进，方向或费用扩大再确认。

### 7.1 Dola 任务包的内容

```text
local/episodes/V001/dola_package/
  README.md                 # 按顺序操作，不需用户重新拼提示词
  manifest.json             # 任务编号、版本、参数、引用文件与状态
  prompts/
    S01.txt
    S02.txt
  references/               # 仅具有相应输入使用依据的素材
  incoming/                 # 人工下载的原始生成文件
```

这是后续目标结构，本轮未创建。提示词应完整可复制；外观约束和场景约束固定；每个镜头只包含必要动作。需要人物/产品图时先明确取得方式和成本，不能隐藏额外图片 API 消耗。

`manifest.json` 每项至少记录：`episode_id、shot_id、prompt_version、prompt_file、input_refs、target_seconds、requested_seconds、resolution_requested、model_observed、generation_status、attempt_no、usage_record、output_path、output_sha256、quality_status`。

### 7.2 Dola 账号能力核验表

核验实际官方域名/应用、本人可正常控制的账号、适用地区、页面显示模型、支持输入、可选时长、画幅、下载质量、是否含音轨/标识、剩余额度和扣费方式。账号与私有截图留本机；公开仓库只保存脱敏结论。

**页面未显示模型名就写未显示，不能根据画面猜成 Seedance 2.5。** 首次提交前读取真实提示；看不到免费或扣费依据就不假定免费。Dola、国内豆包、即梦、Dreamina、BytePlus 和 HypiHub 分别核验，不共享假定额度。

### 7.3 生成长度的两条分支

- 实际支持约 30 秒且符合使用条件：可先尝试一个整段任务；仍需检验情节、动作和长度，不把“提交一次”当最终合格。
- 只支持更短时长：按该账号实际可选值拆成数个任务，再由 Hypit 拼成目标时长。例如账号支持 10 秒时，可以设计三个主要段落；计费按实际生成而非剪后秒数计算。

连基本视频功能都没有时，标为 `blocked_capability`。能用更短片段完成时不因无法直出 30 秒而放弃，但也不擅自切到付费服务。

## 8. 在 Dola 人工生成与下载：不是免费 API

首轮衔接名称为 `manual_dola`，这是**我们内部的任务模式名称，不是 Hypit 已存在的 Provider 名称**。

1. 用户在自己的正常会话中打开实际视频入口，按任务包上传允许作为输入的素材并粘贴对应提示词。
2. 选择当前可用的时长、画幅等参数，记录页面实际显示值；确认使用范围与消耗后提交。
3. 记录任务/会话定位信息与开始时间；等待完成。没有 API 时，程序状态是 `awaiting_manual_generation`，不是假装后台调用。
4. 通过服务提供的下载功能保存输出至 `incoming/`，按镜头和尝试编号登记；不把预览截图当视频。
5. Codex 读取实际文件，验证可播放、时长、声画轨道、尺寸、哈希与对应任务；用户人工复核内容。

不建立账号池、轮号突破额度、验证码绕过、设备伪装或未经允许的输出提取。未来可在许可、额度和预算内接正式 API，但不是首条样片的必需前提。

### 8.1 片段审核与局部重做

每段必须检查角色外观是否保持、主要动作是否做到、是否出现多余角色/畸形/文字乱码、是否保留笑点关键动作、实际画幅与时长是否可用、音频是否需替换。

结果为 `accepted / trim_fix / regenerate / rejected`；记录具体失败原因，不只写“不好看”。可裁切修复的先剪辑修复；需要重生成的只重做该段，不整片重抽。

默认每镜头最多两次重生成，并受实际可用额度和已批准预算共同限制。仍不合格就简化动作、改分镜或报告阻塞。免费尝试也记录次数和主动工时。

账号额度用尽或下载失败不清空项目；保留已经合格的片段，更新缺失任务。任何更换账号或服务都不被包装成自动无限产能。

## 9. 回填 Hypit、合成与人工验收最终视频

### 9.1 回填与渲染

将已经接受的 Dola 文件绑定到对应镜头；原始文件不可覆盖。Hypit 组织时序、裁切、图形/排行、中文字幕、音轨与最终 Film/Render，保留 Source 与构建产物。[S2]

首次实际执行前，确认构建不会顺带触发示例中的图片、视频或托管语音服务；尤其不要复制包含付费生成节点的示例后直接运行全构建。简单无对白故事无需强行部署重型语音对齐。

FFmpeg/ffprobe 可作为媒体检查、编码或必要的本地辅助；不能不说明就用自研剪辑程序替代 Hypit 主链路。Hypit 本机渲染失败时保留日志与项目，可交付标注为临时预览的人工粗剪，但不将其计作 Hypit 端到端验收通过。

### 9.2 目标交付

本机 `local/episodes/V001/final/V001_v1.mp4`，配套 Hypit 源文件、运行记录、媒体信息、审核记录和成本。

默认竖屏 9:16，目标约 30 秒；优先原生条件支持的清晰输出。720p 素材放大到 1080p 必须如实记录，不声称画质变成原生 1080p。输出尺寸、帧率、时长按实际媒体文件读取。

片中字幕和音轨有对应使用依据；保留所需来源及 AI 标识，不用去标识处理伪装成真人拍摄。技术质量检查与发布许可检查分别记录。

### 9.3 人工最终验收表

| 项目 | 检查方式 | 不通过的处理 |
| --- | --- | --- |
| 故事 | 不看说明完整播放，能否讲清开头和结尾 | 改剧本或剪辑，不靠加特效 |
| 画面 | 逐段看人物、动作、道具和衔接 | 只退回问题镜头 |
| 声音 | 手机外放检查是否突兀、破音或缺失 | 调整/替换有许可音轨 |
| 字幕 | 检查错字、速度、对比度和界面遮挡 | 调整字幕层 |
| 新创作 | 对照参考片，确认不是原片换字幕 | 退回改写或重新选片 |
| 文件 | 真正播放 MP4 并核对实际媒体信息 | 修复构建，不接受只有日志成功 |
| 来源与用途 | 检查输入、输出、配乐等使用范围 | 阻塞对应发布/交付步骤 |

用户给 `approved / revise / rejected`，记录具体成片版本及哈希。生成片段通过不代表整片通过；换字幕、音轨或画面后应保留新版本，相关审核重新确认。

## 10. 状态、证据和恢复机制

建议主状态顺序：

```text
candidate_found → source_verified → reference_downloaded
→ reference_approved → hypit_analyzed → storyboard_approved
→ dola_package_ready → awaiting_manual_generation
→ assets_received → assets_approved → hypit_rendered
→ final_approved

后续：ready_to_publish → published → metrics_collected → reviewed
```

另记录 `blocked_access、blocked_rights、blocked_capability、blocked_budget、generation_failed、render_failed、revision_required` 及所在步骤；阻塞时保留上一次成功状态、原因和恢复动作。

每次人工审核需绑定输入版本/哈希，防止参考片、分镜或素材已经变了，仍复用旧批准。手动衔接必须能从缺失片段继续，不要求重跑选片、下载和全部生成。

`final_approved` 表示该样片通过内容与技术验收，不等于 `ready_to_publish`；后者还需许可、平台条件和用户发布批准。不能用自动时间戳或空文件制造完成证据。

## 11. Codex 的任务顺序：P0 先做到底

以下全部为计划，尚未执行。只在用户批准执行后修改本机或安装；本文件更新本身不代表这些操作已经获授权。

### T0：核验工作区、Hypit 与 Dola 前提（P0 的准备工作）

读取本文件、实际存在的项目指令和 HANDOFF；核对仓库、分支、未提交修改。检查 Hypit/Skill、所需运行环境和媒体工具的真实状态。列出缺依赖、需要的最小安装范围、Dola 本人需提供的脱敏能力信息和用途限制。

**验收：** 报告什么可直接做、什么待授权、哪个环节被阻塞。不要把“检查了环境”当本项目完成。无需建设网站、服务器、仪表盘或另一个视频框架。

### T1：真实候选与下载（P0）

按第 3 节寻找真实 TikTok 候选，按第 4 节保存允许保存的参考片；形成候选卡和最多三条可审素材。可访问受限时使用正常人工方式，不伪造搜索结果。

**产物：** `candidates.csv`、对应来源记录、真实本地参考文件与媒体信息。

**验收：** 用户能打开候选链接和参考片；原始显示指标与日期可追溯。没有做过下载不得标记完成。

### T2：人审选片与 Hypit 拆解（P0）

取得参考片的人审结论，用真实素材进行 Hypit/Agent 分析；形成中文改写、分镜、输入素材方案与拟生成范围；用户审核一次明确版本。

**产物：** `reference_review.json`、`analysis.md`、`storyboard.csv`、`storyboard_review.json`、Hypit 作者源文件及配置雏形。

**验收：** 清楚标明原片的抽象结构、新片改动和每个镜头任务，不把自拟练习片替代所选参考输入。

### T3：Dola 生成包与人工提交（P0）

把第 7—8 节变成可复制提示词、允许输入的参考资产和清单。用户按实际服务范围操作 Dola，下载后回填；程序如实停留在等待人工资产的状态。

**产物：** `dola_package/`、任务记录、Dola 原始输出、片段审核与重做清单。

**验收：** 存在来自实际 Dola 任务的可播放文件，参数和消耗可追溯；没有宣称虚构的 Dola API 集成。

### T4：Hypit 合成与最终审片（P0）

将通过审核的素材回填 Hypit，组织字幕、声音、图形与时序，渲染并人工检查。只在必要处写局部辅助工具，不从零造一个渲染系统。

**产物：** 最终 MP4、可编辑 Hypit 项目、真实构建记录、媒体探测结果、`final_review.json`、成本记录。

**验收：** 满足第 0.2 节的全部条件。临时合成成功但 Hypit 失败要分别报告，不能混为链路完成。

### T5：复验一次局部修改（P0 的可复用性检查）

依据实际审片反馈修改一个镜头或字幕，复用未变动且已通过的素材；重新渲染、核对版本和增量消耗。

**验收：** 不必重新下载参考片或重新生成全部镜头；交接记录能让另一位执行者继续修改。不得为了测试恢复而额外调用未批准的付费模型。

### T6：国内抖音发布（P1）

P0 合格并完成使用范围与平台核验后，用户人工发布。记录发布的最终文件哈希、标题、封面、声明、实际链接和时间。仅在未来有明确需求、官方能力与授权时再设计自动发布。

### T7：数据跟踪与复盘（P2）

依据用户提供或明确授权获取的后台数据记录 24 小时、72 小时、7 日快照；生成成本和内容复盘。P0 前不开发实时监控系统，也不暗示已经在后台自动监控。

### 工程验证要求

一任务一可验收交付。若新增脚本，先写针对性测试再实现；必要用例包括：中文/空格路径、无文件、伪 MP4、文件损坏、时长不足、无音轨、重复文件、输出已存在、路径越界、错误镜头绑定、审核版本过期、生成未完成、渲染失败、未知扣费。

脚本不接受任意 shell 命令，不向任意远程地址上传参考素材；凭据不得写进日志。测试命令以实际创建的测试结构为准，没运行就写未执行，不能提前写测试通过。

## 12. P1：上传国内抖音，不上传参考原片

发布物必须是通过审核的新成片，不是下载的 TikTok 文件。内容方向先保持一个账号，不一开始做矩阵、买粉、刷互动或付费投流。

本人在当前抖音发布入口选择最终文件，检查画幅、封面、标题、字幕、配乐、AI 生成声明和实际可见范围；最后由用户确认发布。具体界面路径以当时账号为准，不假定已有自动上传 API 权限。

首次发布前单独确认模型服务与所有声画素材允许当前用途。Dola 的私人/非商业条款意味着不能默认把其测试产物投入商业账号运营；“以后买 API”也不自动追溯改变旧素材许可。[S3] 如需重新生成，保留同一故事/编排项目并明确更换来源及版本。

发布记录至少有：`episode_id、version、file_sha256、title、published_at、post_url、platform_post_id_if_available、ai_declaration、visibility、review_status`。

发布显示成功后，再实际打开作品确认处理完成、声音和画面正常。审核中与已公开分开记录；未发布不可填假链接。未经确认不删除旧作品或重复上传近乎同一版本。

## 13. P2：监控视频、看数据、指导下一条

### 13.1 第一版怎么获取数据

先使用用户本人创作者后台的导出、截图或手工录入；只处理用户提供或明确授权的数据。公开播放数据无法替代本人后台的平均观看、完播或归因关注等指标。

发布后目标观察点为 24 小时、72 小时与 7 日。错过观察点时记录实际观察时间和距发布时间，不把晚取数据伪装成准点数据。需要定时提醒或授权接口后再建立，不因策划写了“监控”就声称已经开启。

### 13.2 记录字段

```text
episode_id,version,published_at,observed_at,elapsed_hours,
views,avg_watch_seconds,completion_rate,likes,comments,shares,saves,
attributed_follows,traffic_paid,platform_warnings,
estimated_revenue,settled_revenue,source_of_metrics,notes
```

缺失值留空；相同观察点和相同统计口径才比较。播放为 0 时比率为空；循环播放可能使平均观看超过片长，不机械裁掉。

关注观看比例、分享率、平台实际提供的归因关注率，同时看质量、返工、每条工时与成本。用同栏目多条作品的中位表现辅助判断，不只拿最好的一条证明方向有效。

### 13.3 什么结果决定下一步

观看弱先检查开场理解与节奏；有播放无关注检查角色和系列理由；有关注无消费意图不强行认定能卖宠物用品。单条爆发要用新的故事复验，不立即扩大预算。

20 条是 P0/P1 跑通后的可选试验规模，不是必须烧完的指标。先探索三个结构各少量作品，再复验较有希望的结构；最后单独测试真实商业需求。

暂停条件：预算耗尽、使用范围不明、账号/平台问题、持续返工无法控制。不会因为几百播放就断言账号废了，也不以“再做一百条一定会起量”无限加码。

## 14. 内容方向与后续二十条实验，不能抢在 P0 前面

主方向暂保留 AI 萌宠拟人轻喜剧。角色草案为橘白猫“豆丁”和灰猫“灰灰”，外观简单稳定；先由选定参考的改写需求决定是否采用，不把固定角色设定当成不能调整的教条。

三个栏目候选：日常误会反转、简单挑战排行、中文生活共鸣。后续试验可按 12 条探索、6 条复验、2 条需求探索安排，但每批先审剧本和成本，不预生成全部。

v1.0 的备用创意保留为后续灵感：豪华猫窝与纸箱、抢座、等饭会议、收纳露馅、纸箱选座、三种等饭姿势、静止挑战、守坐垫、五分钟会议、周末闹钟、同事说很简单、下班前一分钟任务。它们不是已核验的 TikTok 爆款，不用于冒充首条真实输入。

海外高播放也不保证中文平台有效；猫咪观看人群不等于宠物消费人群。先验证内容和持续制作，再验证受众需求与成交。

## 15. 成本与收益：沿用低投入原则

### 15.1 费用记录

`单片直接成本 = 该片所有已扣费生成任务 + 图片/声音等费用 + 可归属其他支出`。失败未退款、弃用镜头和重试计入，不能只算最后采用的片段。

`试验现金净流出 = 实际付款 - 实际退款 - 已结算到账收入`。订阅付款和积分消耗分别记，不能重复相加；剩余积分不是退款。既有工具可能不增加现金，但仍记录消耗和工时。

30 秒算术示例（不是供应商报价）：若实际生成 45 秒，另花 1 元做其他素材，则假设每计费秒 0.05/0.10/0.30 元，对应 3.25/5.50/14.50 元。真实计价若按任务、积分或 token，则使用实际规则，不强行换算统一每秒价格。

付费前核验一次实际报价、支付周期和自动续费；未知费用不当免费。免费账号额度不按卖家口径估算为永久库存。每个镜头超重试上限后先简化，不能自动换贵模型。

### 15.2 变现路径

平台创作激励、商品推广佣金、品牌/星图任务、客户视频制作服务分别核验。上传不等于分成；粉丝、有效粉丝、互动粉丝不是相同指标。此前聊天中的具体门槛不作为本账号已满足条件的证据。

首轮收入预算为 0。预估收入、待结算和已到账分开；回本以扣除退款后的真实到账与投入比较。任何收益路径都不能用播放量乘一个未经核验的固定单价预测。

AI 虚构剧情不能冒充真实商品使用效果。商业推广、客户交付的授权与结算条件另核对；不因能渲染视频就认为可以接任何订单。
